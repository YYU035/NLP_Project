# Historical records

These dated records preserve the implementation, tests and plans at their original snapshots. Use the [root README](../../README.md), [current architecture](../architecture/overview.md) and [results index](../results/index.md) for current navigation.

- `integration/`: original handoff notes, plans, API policy and QC. Counts, defaults, contributor paths and commands may be superseded.
- `reproduction_tools/`: exact historical owner-checkout QC source, retained for provenance; these are not current release commands.
- `poster_20261109/`: original A3 poster/build inputs, predating the primary-policy promotion.
- The [Archify bundle](../architecture/project_map/) retains its historical architecture snapshot and embedded source links.
- Frozen scientific studies remain together under root `evaluation/`, preserving original measurements and reports.

The migration manifest records old-to-new paths. Current source gets a new release identity; it must not silently replace an older frozen hash. Historical reproduction may require the recorded source snapshot/model/data protocol. Default root tests must not assume old owner Git objects exist in a shallow clone.

Failed IG checks, rejected local-generation outputs, regressions and blank human-review forms remain evidence. Moving files does not turn them into successful scientific validation.
